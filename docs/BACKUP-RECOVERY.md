# 备份与恢复

完整备份包含业务数据、审计记录、账号密码哈希和上传图片。每个文件有 SHA-256 与大小校验；恢复后再对照原包检查数据库和文件。备份只用于本地运维，不通过商家网页下载，不加入 Git。

## 自动备份

使用当前版本的 `npm start` 启动服务后，数据库连接就绪时检查是否到期：首次生成一份完整备份，此后默认每 24 小时一次。失败后 15 分钟重试，任务不会并行叠加。服务正常退出时等待正在进行的备份结束。

服务重启会读取上次备份状态；如果已经到期，启动后补做。主机或 Node 关闭期间不能执行定时任务，进程守护是独立的运行条件，不能以备份定时器替代。

| 配置 | 默认 | 用途 |
| --- | --- | --- |
| `SHOP_DATA_DIR` | 项目下的 `.local` | 账号、上传图片及备份状态所在目录 |
| `SHOP_BACKUP_DIR` | 数据目录下的 `backups` | 完整备份包存放位置，可配置为受保护的其他磁盘目录 |
| `BACKUP_INTERVAL_HOURS` | 24 | 备份周期，最小 1 分钟 |
| `BACKUP_KEEP` | 14 | 至少保留最近 14 份完整包，最小为 2 |
| `BACKUP_MIN_AGE_DAYS` | 7 | 同时保留最近 7 天的完整包，最小为 1 |

清理发生在成功生成并校验新备份之后。只有超过保留份数、同时早于保留天数的完整包才会清理；未完成、损坏、不属于本工具的目录均保留。旧格式的业务快照不会自动清理。

查看最近执行结果：

```sh
npm run db:backup-status
```

`NOT_STARTED` 表示该数据目录还没有自动执行记录。`error` 非空表示最近备份失败，`retentionError` 表示清理失败但已生成备份，`overdue` 表示超过下次执行时间仍无更新。状态文件不能单独证明进程仍在运行，还应检查服务健康状态和进程。

## 手动备份与校验

在项目根目录执行：

```sh
npm run db:backup
npm run db:verify -- .local/backups/<命令返回的备份编号>
```

如果配置了 `SHOP_BACKUP_DIR`，校验时使用该目录内对应的备份包。输出只给备份编号和数量，不打印机器路径、密码或数据库连接凭据。

备份包包含：

- `manifest.json`：格式版本、数据库名、快照版本、文件校验信息和数量。
- `business.json`：商品、订单、地址、门店设置、库存流水、幂等键等业务状态。
- `audit.json`：与业务状态在同一个数据库快照中读取的操作记录。
- `auth/accounts.json`：账号、角色、身份编号、密码盐与哈希；不含明文密码和会话。
- `uploads/`：上传图片。商品、订单等业务状态引用的图片缺失时，备份失败。

源码与随代码提供的图片由 Git 管理。隧道令牌、明文测试密码、浏览器会话和机器专用启动脚本不打入备份包。恢复后使用原账号密码登录，旧会话需要重新登录。

校验值用于发现损坏，不代表包来自可信来源。只恢复自己保存的备份。备份含订单地址、联系方式和账号哈希，应放在只有运维人员可访问的位置；不能作为小程序侧联调资料分发。

## 恢复演练

恢复必须使用新的 `pet_shop_restore_` 数据库名称和不存在的数据目录。当前数据库和原数据目录不会被替换。

```sh
npm run db:restore -- .local/backups/<备份编号> pet_shop_restore_YYYYMMDD
```

默认恢复文件放到数据目录下的 `restores/pet_shop_restore_YYYYMMDD`。也可以用第三个参数指定新的数据目录，其父目录必须已存在。

工具先检查整个包，再复制账号与图片、恢复数据库，并重新比对业务、审计和文件。数据库中额外保留一条恢复操作记录。成功返回 `verified: true`，并生成 `restore-report.json`。

失败时保留 `RESTORE_INCOMPLETE` 标记，不能把这个目录当作可运行数据目录；服务会拒绝使用它。失败的目标只供排查，再次恢复请换一个新库名和新目录，不要重用或覆盖现场。

恢复完成不自动切换服务。正式切换前应停止旧 Node，确认启动配置同时指向恢复出的 `MONGODB_DATABASE` 与 `SHOP_DATA_DIR`，保留原库和原目录，再启动并检查登录、商品图片、订单与库存。数据库连接和 HTTPS 来源配置也需与目标环境一致。

旧的格式 1 `business.json` 仍可使用原命令恢复，但只恢复业务数据；输出会明确标记 `legacy: true`，不能视为完整恢复。
