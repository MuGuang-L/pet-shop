# 服务启动与恢复

当前联调服务已于 2026-10-26 切换到受管启动，数据库、Node 和 NATAPP 均由同一守护实例管理。Windows 当前用户的登录任务已登记；任务启动、后端退出恢复及守护进程退出恢复均已现场验证。实际注销登录或整机重启后的触发仍待验收。

## 受管启动

先将 `deploy/runtime.example.json` 复制为 `.local/runtime/config.json`。配置只留在本机，不提交 Git。

- `manageMongo: true`：启动本项目持久化 MongoDB，固定回环端口 27018、副本集 `petshop`。沿用原数据目录，停止时不删除数据。
- `manageMongo: false`：只检查外部 MongoDB 是否就绪，不启动或停止它。连接信息通过私有环境变量 `MONGODB_URI` 提供。
- `publicOrigin`：填写当前 HTTPS 访问入口，不能带页面路径。
- `natapp.enabled: true`：启用已有 NATAPP 客户端及私有配置文件。示例中只包含相对文件位置，令牌仍在原私有配置中。

在项目终端运行：

```sh
npm run service:check
npm run service:start
npm run service:status
npm run service:stop
```

`check` 只检查配置、账号文件、端口和已有隧道进程，不启动服务。`start` 按数据库、后端、隧道的顺序启动，上一项健康后才启动下一项。

旧入口还在运行时，会返回 `EXISTING_SERVICE_ON_4173`、`EXISTING_SERVICE_ON_27018` 或 `EXISTING_TUNNEL_PROCESS`。这时原服务继续运行；需要安排一次切换，先核实并正常关闭旧入口，再启动受管入口。不要同时运行两套启动脚本，也不要按进程名称批量结束 Node 或 MongoDB。

## 恢复规则

- 只对本次启动持有的子进程响应退出事件。确认退出后重试，间隔从 1 秒逐步增加，最多 30 秒；连续健康运行 60 秒后恢复初始间隔。
- 探测失败、请求超时、数据库断连或 IPC 报错都不等于进程退出。进程仍活着时标为 `unhealthy`，不据此重复启动或强制重启。
- 本地和公网健康检查携带同一个随机运行标记，避免把另一个服务的响应误判为本实例已恢复。标记不含本机文件位置、账号或令牌。
- 停止时先停隧道，再等待后端请求、定时任务和备份结束，最后停止数据库。Windows 工作进程通过 IPC 正常清理，避免直接终止数据库进程。
- 本机单成员副本集通过 MongoDB 的 `shutdown` 命令关闭，使用 `force: true` 处理没有其他可选举成员的情况，并给出 5 秒静默期；它可能中止仍存在的其他数据库操作，所以先等待后端结束。只有确认持有的数据库进程已退出，才清理启动助手；关闭命令失败或等待超时不回退到操作系统强杀。命令语义见 [MongoDB 官方说明](https://www.mongodb.com/docs/manual/reference/command/shutdown/)。
- 某项停止超过 30 秒会报告 `STOP_TIMEOUT`，保留进程和其依赖，不宣称已经关闭。检查状态后可以再次请求停止。
- 父进程断连时，Node 和 MongoDB 工作进程会执行清理；隧道包装进程会关闭它持有的客户端。隧道每次启动前还会检查是否存在同路径旧客户端，避免重复连接。被强制终止的包装进程留下的客户端需要核实处理，不会按名称自动杀掉。

同一项目只能有一个守护入口。状态从本地控制通道读取，不以旧 PID 文件或旧状态文件证明进程仍在运行。停止命令需要本机私有控制令牌。控制通道不监听公网 TCP 端口。

状态和简短事件记录保存在 `.local/runtime/`。事件只记录服务名、进程号、退出码及重试时间，不写入启动参数、环境变量、令牌和完整文件位置；事件文件轮转保留三份。状态或日志写入失败会单独显示，不因此结束正在运行的业务进程。

## Windows 登录恢复

运行 `scripts/install-runtime-task.ps1` 可以为当前用户登记登录任务；运行同一脚本加 `-Remove` 只撤销任务，不停止正在运行的服务。安装脚本检查配置和已有任务归属，不自动立即启动服务。

任务在当前用户登录后隐藏启动。`run-supervised.ps1` 等待守护进程实际退出，非零退出码时每隔一分钟重试，最多三次；正常停止立即结束，不重试。重试由启动脚本负责，任务计划程序不额外叠加失败重试。现场发现仅设置任务的失败重试未能在手动启动后的进程退出中恢复，因此不再依赖这一设置。不保存 Windows 密码，不要求提升权限。它依赖当前用户登录，不能替代正式服务器在无人登录时启动的系统服务，也不能让断电的主机继续提供服务。

## 验收边界

自动测试覆盖退出重启、退避、探测超时、退出与探测竞态、依赖顺序、停机超时、外部数据库不被停止、本地控制鉴权、父进程断连清理、端口冲突和运行标记。真实子进程故障测试只运行专用测试工作进程，不监听业务 HTTP，也不停止共享数据库或隧道。

Windows 启动脚本另有实际子进程测试：正常退出不重试、失败后恢复、连续失败最多三次重试并保留非零退出状态。CI 在 Windows 执行这三个测试；Linux 作业不执行 Windows 脚本。

## 2026-10-26 现场切换与故障恢复

- 切换前生成完整备份 `backup-2026-10-26T15-39-50-592Z-d42ad00b`：4 个商品、12 笔订单、85 条审计、3 个账号及 3 张上传图片，并保存业务集合基线。
- 正常关闭已核实的旧数据库后，数据库辅助进程自行退出，切换脚本的再次身份检查遇到退出竞态而停止。检查确认原进程和监听端口已释放后，从启动受管服务步骤继续，没有重复停机或强杀数据库。
- 受管后端退出后，守护器拉起新进程；数据库和隧道不重启。随后正常停止整套服务，通过 Windows 计划任务重新启动成功。
- 使用修复后的启动脚本运行，终止已核实的守护进程；其工作进程退出清理后，启动脚本等待一分钟，自动启动新守护实例。数据库、后端、隧道均重新健康，运行标记发生变化，本地与公网标记一致。
- 每次恢复后通过 HTTPS 验证买家和商家登录、订单读取、角色隔离、商家页面及全部上传图片。原有业务集合和审计与切换前逐条一致；账号记录及图片内容不变。
- 完整本机测试 245 项通过、0 失败、0 跳过。私人启动入口已改为调用受管任务；私人后端重启入口只终止守护器持有的已核实后端，等待守护器拉起，不再启动独立副本。

本轮没有重启电脑或注销当前用户，所以不能把任务手动启动成功写成实际开机登录验收。真机网络切换、异机备份和正式部署条件继续记录在上线清单中。
