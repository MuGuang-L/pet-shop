## 自提时间

商家经营设置中的“预计备餐时间”控制最早可选时间（0–240 分钟）。买家可选择未来三天内、符合北京时间营业日与营业时段的 15 分钟时间点，也可选择尽快取餐。尽快取餐会保存为下一个实际可用时段。订单记录创建时的时间快照，后续修改营业设置不会改写旧订单。自提时间同时显示于买家订单详情和商家订单详情。

## 会员储值

商家后台 → 经营设置 → 编辑设置 → 会员储值：设置开关、充值档位和使用说明。默认关闭充值，默认档位为 100 / 200 / 500 元；每档实付支持 1–5000 元，最多六档。每档可设置高于实付的到账金额（含赠送部分，最高 10000 元）；微信按实付收费。关闭充值不影响已有余额消费。

小程序“个人中心 → 会员储值”查看余额、选择充值档位和最近 50 条流水。充值生成独立充值订单，使用现有微信支付渠道；只有服务端验证支付金额与交易身份后才入账。模拟付款不能给储值账户加钱。付款中断时可从“我的订单”找到充值订单继续处理。

普通商品待付款订单可选择余额支付，服务端在保存订单的同一数据库事务中扣减余额。余额不足整笔失败；重复支付请求不会二次扣款。余额支付订单售后使用现有商家审核流程，完成退款时退回会员余额，不提交微信退款。

充值退款只支持整笔原渠道退回：买家申请售后，商家批准时先从可用余额扣回当时的全部到账金额（含赠送部分），微信退回原实付金额；余额不足时审核整体失败。退款处理中这笔钱不可消费；微信退款失败时保留待退状态并按原退款单重试。充值过期或取消后微信才确认付款时，不计入余额，沿用现有迟到支付退款流程。

“经营设置 → 查看会员账本”可查询会员余额和最近流水。完整流水保存在数据库，不提供任意改余额入口。

## 部署与验收

需要同时更新云托管后端和小程序；仅重新编译小程序无法启用新接口。已有 MySQL JSON 状态和 MongoDB 元数据会按需增加钱包字段，不需要清库。

上线收取充值款前，应使用门店实际微信商户完成充值、余额消费、商品退款、充值原路退款的真机验收；本地自动化使用模拟支付接口响应，不代表真实商户支付授权已经通过。
