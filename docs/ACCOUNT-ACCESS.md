# 账号与登录可靠性

当前使用独立的模拟买家账号和商家账号。小程序侧不能调用商品维护、发货、库存或售后审核接口；服务侧也不能冒充买家下单。买家读取订单、地址和售后时继续按服务端身份隔离，客户端传入的角色字段不能授权。

## 登录与会话

- 密码校验使用异步 scrypt，与现有账号文件中的盐和哈希兼容，不改密码、不迁移业务数据。
- 同一 Node 进程最多同时执行两个密码校验。超出时立即返回 `503 LOGIN_BUSY` 和 `Retry-After: 1`，不堆积密码校验任务；已有会话请求和健康检查可继续处理。
- 每个已配置账号一分钟最多十次尝试，成功后清除该账号的失败计数。所有未配置的用户名共用一个计数桶，避免随机用户名撑大内存。
- 全服务一分钟最多接收六十次密码校验，成功登录也计入。限流返回 `429 LOGIN_RATE_LIMIT`，`Retry-After` 表示当前窗口剩余秒数。预算不依赖可伪造的代理 IP 请求头。
- 会话有效期八小时。单账号最多八个会话，全服务最多 256 个；超出时淘汰最早签发的会话。访问过期会话时立即清理，登录时也会清理过期记录。
- Cookie 保持 HttpOnly、SameSite=Strict；配置 HTTPS 公网入口后使用 Secure。显式提供了无效 Authorization 时，不回退使用 Cookie 身份。
- 账号文件中角色、哈希格式、重复账号名或重复身份 ID 不合法时，服务启动会拒绝该配置，不返回文件内容或位置。

这些限制面向低 QPS、单进程的模拟店铺，不能替代网络入口的流量防护。计数和会话保存在内存中；服务重启后需重新登录。真实微信身份和支付仍需单独接入。

## 两侧提示

小程序侧和商家网页均区分账号密码错误、登录频繁、登录繁忙和网络失败。登录不自动重发，失败不清空输入内容。登录错误不再提示核对商品是否已保存。

## 验证与生效

2026-10-26 完整 219 项测试通过，包含实际异步密码校验、隔离 HTTP 中校验等待期间继续访问健康和已有会话、限流恢复、随机用户名、会话上限、非法请求和账号配置冲突。现有三个账号只读校验通过。

这轮后端改动尚未加载到当前共享 Node 进程，需在后续统一重启或受管切换时生效。商家网页脚本刷新即可更新提示；小程序需重新编译。没有向共享入口发送频繁登录测试，也没有修改已有账号、订单或库存。
