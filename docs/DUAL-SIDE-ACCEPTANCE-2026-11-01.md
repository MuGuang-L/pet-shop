# 双端经营流程验收 · 2026-11-01

基于联调分支提交 `85e2019`，另补充订单中心常驻返回、首页入口。支付接入代码、密钥、回调配置均未修改，未发生真实扣款或资金退款。

## 本轮验证范围

服务侧使用独立 MySQL 8.4.7 数据库及本地 HTTP 服务，支付模式为 simulation。小程序侧加载当前真实页面控制器、API 和结算模块，通过 HTTP 访问同一服务；微信 API 使用测试桩。商家操作使用实际浏览器页面点击和输入。

这验证了小程序业务逻辑、商家网页与数据库之间的闭环，但不等同于两端生产环境、手机实机全流程验收。

## 结果

| 流程 | 实际结果 |
| --- | --- |
| 小程序控制器创建自提、外送订单 | 各一单，库存从 28 减至 26 |
| 商家外送发货 | 登记配送单号后进入配送中 |
| 买家收货、申请退货退款 | 通过当前控制器请求成功，商家可见申请 |
| 商家审核，买家提交退货信息 | 售后进入 RETURN_TRANSIT |
| 商家验收并将一件商品重新入库 | 库存恢复至 27，进入待退款 |
| 商家完成模拟退款记录 | 买家读回 REFUNDED / SUCCEEDED |
| 自提备货、核销 | 错误提货码被拒绝，正确提货码完成核销 |
| 买家再次读取自提订单 | COMPLETED |
| 最终库存 | 27，与 28 - 2 + 1 一致 |

退货运输步骤首次断言使用了错误的预期状态 WAIT_RECEIVE，实际返回 RETURN_TRANSIT；已修正测试脚本预期，最终状态和库存复核通过。此项不是业务代码故障。

全量回归：313 项，280 通过，0 失败，33 项跳过。跳过项不计为通过；上述 MySQL 实际操作为独立补充证据。

- 微信开发者工具已显示当前 TDesign 订单列表和云端订单；个人中心到独立订单中心的进入操作已观察到。
