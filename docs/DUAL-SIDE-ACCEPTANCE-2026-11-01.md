## 本轮验证范围

服务侧使用独立 MySQL 8.4.7 数据库及本地 HTTP 服务，支付模式为 simulation。小程序侧加载当前真实页面控制器、API 和结算模块，通过 HTTP 访问同一服务；微信 API 使用测试桩。商家操作使用实际浏览器页面点击和输入。

这验证了小程序业务逻辑、商家网页与数据库之间的闭环，但不等同于两端生产环境、手机实机全流程验收。

## 结果

| 流程 | 实际结果 |
| --- | --- |
| 小程序控制器创建自提、外送订单 | 各一单，库存从 28 减至 26 |

全量回归：313 项，280 通过，0 失败，33 项跳过。跳过项不计为通过；上述 MySQL 实际操作为独立补充证据。

## 重新编译故障复查

重新编译时捕获明确错误：`module 'config.local.js' is not defined`，随后报告页面未注册，模拟器白屏。本地配置文件存在，不能将该现象仅归因于点击工具。

将配置入口的引用改为显式 `require('./config.local.js')`，重新打开项目进行冷编译后，首页恢复，模块错误未再出现。由于同时重建了开发工具缓存，尚未单独证明省略扩展名是唯一原因。

冷编译后的实际点击已通过：个人中心进入售后订单、页面返回个人中心、进入全部订单、切换待付款筛选、订单页回到首页。再次点击编译后首页正常，控制台仅显示预加载警告，没有复现模块错误。配置初始化与订单导航专项测试 7 项通过，129 个 JS/JSON 文件检查通过。支付接入未修改。
