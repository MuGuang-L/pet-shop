# 快递配送与物流查询

当前 DELIVERY 表示通过快递公司寄送，PICKUP 表示到店自提。业务订单号和快递单号独立保存：买家打开自己的订单即可查看关联运单，不需要再手动输入快递单号。商家发货必须选择快递公司，并填写 6～32 位实际运单号；备注选填。当前支持顺丰、中通、圆通、申通、韵达、京东、EMS、邮政包裹、德邦和极兔。

## 服务选择（2026-11-01 核对）

本版接入快递100实时查询 API。其官方帮助说明企业账号有 100 单免费联调额度，未充值可测试；实际额度、有效期及公司权限以注册后的后台为准，不承诺永久免费。[免费测试说明](https://api.kuaidi100.com/document/ceshidanlaing)、[账号测试额度](https://api.kuaidi100.com/document/jiekouceshidanliang)。

快递鸟公开套餐页标注免费基础版每日 100 单订阅、500 次即时查询，但主流公司免费覆盖有限，列明不支持顺丰、中通、韵达、京东等，因此门店承运公司未确定时不优先采用。该页的额度与公司列表需向其后台再次确认。[套餐说明](https://v2.kdniao.com/membership)。

## 注册与配置

1. 在 [快递100 API 平台](https://api.kuaidi100.com/) 注册企业 API 账号，按页面要求补充资料。
2. 找到“快递信息实时查询”服务，确认测试额度及所用快递公司的权限。这里不需要开通电子面单、上门取件或地图服务，也不要求先充值。
3. 获取主账号的 Key 和 customer 授权码，在微信云托管服务环境变量中设置 `KUAIDI100_KEY`、`KUAIDI100_CUSTOMER`。不要把密钥放在小程序、Git 或截图中。本版使用主账号接口，子账号网关不是同一地址。
4. 发布包含此改动的后端版本，再重新编译上传小程序、更新体验版。商家后台刷新后即可选择公司录入运单。
5. 使用门店自己的实际包裹验证：公司与单号、收件手机号、轨迹、查询失败提示、另一买家不可访问。顺丰和中通查询使用订单收件手机号进行校验；如面单使用其他手机号或虚拟号，应先核对资料。

只配置环境变量不会自动发布代码；仅上传小程序也不会更新后端。未配置凭据时，仍可发货并展示公司和单号，但页面明确提示物流服务尚未开通，不生成假轨迹。新发货接口要求 carrier，因此旧商家后台应在服务更新后刷新再操作。

## 查询与状态

后端按登录用户验证订单归属，忽略客户端提供的任意运单号和快递公司，只查询数据库中本单关联的运单。小程序打开已有订单详情会查询物流，也可点击“刷新物流”。物流服务失败不影响付款、订单读取或确认收货。

订单进度与快递轨迹分别展示。商家登记发货不代表快递已经揽收；快递轨迹的签收不自动把商城订单改成已完成，仍由买家确认收货。补发登记新的公司和单号，旧寄件记录保留在订单历史中，新查询使用新运单。历史自配送订单缺少 carrier 时提示联系商家核实，不猜测承运公司。

实时查询接口要求单运单查询间隔至少半小时，本版采用 31 分钟间隔。查询预约及上次结果存储在 MySQL `logistics_cache` 表或 MongoDB 同名集合：跨实例和进程重启复用间隔，失败也冷却，旧请求不能覆盖新预约结果。不是每次点击刷新都请求第三方；页面展示上次成功更新时间。缓存是可重新获取的派生数据，不纳入现有 MongoDB 业务备份包，删除缓存会丢失频率保护，应避免手动清空。

本版按用户查看时查询，没有后台周期扫描、订阅回调或短信推送，不承诺实时秒级更新。对方无轨迹、号码校验错误、额度或网络异常都会显示说明；已有轨迹在失败时保留。服务端只发送公司、运单号及必要的手机号，不发送完整收货地址。密钥和完整上游错误不返回客户端。

接口依据：[快递100实时查询](https://api.kuaidi100.com/document/5f0ffb5ebc8da837cbd8aefc.html)、[英文接口文档](https://api.kuaidi100.com/document/RTqueryEnglish)。

## 门店设置与验收

配送时效改为文字 `delivery.estimateText`，如“通常发货后 2～4 天，以承运公司为准”。旧 estimateMinutes 字段保留兼容，但不再向顾客显示分钟送达。已保存的配送范围、说明与运费不自动覆盖，商家应核实地区限制及费用。

自动化使用测试替身验证签名、响应、缓存和错误路径，真实 MongoDB/MySQL 验证并发预约及持久化；测试不请求真实物流接口、不消耗账户额度。正式账号与真实运单联调、真机视觉确认及云端发布仍待完成。

本次验证：326 项自动测试全部通过，0 失败、0 跳过，包含真实隔离 MongoDB/MySQL。132 个 JS/JSON 检查与微信 WXML/WXSS 编译通过。未配置真实快递100账号，未发起真实物流请求。实时查询由服务端发出，本版不需要配置物流回调域名，也不需要把快递100域名加到小程序请求域名中。
