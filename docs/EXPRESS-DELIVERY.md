# 快递配送与微信官方物流查询

DELIVERY 表示快递寄送，PICKUP 表示到店自提。订单号与快递单号分别保存；商家仍只需选择快递公司、填写运单号并确认发货，买家从自己的订单点击“查看物流”，无需输入单号。

## 当前实现与开通前行为

默认使用微信官方物流查询插件，未开通时仍可正常下单、付款、发货及复制运单号，页面提示查询尚未开通。即使服务器留有快递100密钥，默认也不会调用它；只有显式设置 `LOGISTICS_PROVIDER=kuaidi100` 才使用旧接口，官方查询失败不会自动切换付费接口。

官方查询服务端与小程序入口已实现。当前插件声明关闭，避免尚未取得权限时影响编译和上传；真实微信物流、真机插件页面和消息通知尚未联调。已有线上版本不会随 Git 更新自动生效。

## 开通后启用

1. 管理员在小程序 MP 后台“功能 → 物流服务”申请开通查询组件。官方文档要求开通微信支付且过去 30 天有交易，具体以账号后台为准。模拟支付不满足要求。
2. 确认已获准使用官方插件 `wx9ad912bf20548d92`，在项目根目录运行 `node scripts/wechat-logistics-plugin.js enable`。脚本同时写入 app.json 插件声明（官方当前文档版本 2.1.5）和客户端启用开关。
3. 云托管配置 `WECHAT_LOGISTICS_ENABLED=1`、`WECHAT_APPID`（本小程序）、`WECHAT_MINIPROGRAM_SECRET`（本小程序 AppSecret，不是商户 APIv3 密钥或公众号密钥）。凭据只放服务端环境变量，不提交 Git。本版通过 HTTPS 稳定版 access_token 接口调用，不依赖云调用；如微信后台要求 IP 白名单，配置服务端实际出口 IP。
4. 设置正确的 `PUBLIC_ORIGIN`：用于把订单商品图片的相对路径转为微信可访问的 HTTPS 图片链接。商品图片必须真实存在、可公网访问；订单快照中缺失图片时会提示资料不完整，不用假图片凑参数。
5. 部署后端，重新编译、上传小程序，再用真实手机预览或体验版验证。官方明确插件不能在开发工具模拟器中测试。正式上线仍需小程序审核发布。

无需注册快递100、填写其密钥或购买其套餐。禁用官方查询时设置 `WECHAT_LOGISTICS_ENABLED=0`；需要移除插件声明可运行 `node scripts/wechat-logistics-plugin.js disable` 后重新上传。

## 查询行为与边界

- 打开订单详情只读取查询可用性，不自动弹出官方页面。用户点击“查看物流”后，后端验证订单归属及真实微信支付记录，向微信登记运单并返回 waybill_token；小程序通过 `openWaybillTracking` 打开官方页面。
- 官方接口使用本订单的支付交易号、实际购买者 openid、收件手机号、运单号、商品名称及图片、订单详情路径。不接受客户端提供的任意运单或 openid。商家网页账号不能获得买家查询 token。
- 传运单的 delivery_id 为可选参数；当前由微信识别主流快递运单。门店所用承运公司的识别准确性须真实运单验收，未联调前不承诺全部支持。
- waybill_token 保存在现有 MySQL/MongoDB 物流缓存中，按小程序、订单、买家、支付交易及运单隔离，重复查看和后端重启复用。补发新单号使用独立记录。失败有一分钟重试间隔，不显示上游敏感报错。
- 本版在买家首次点击查询时登记运单，没有新增发货后后台自动订阅任务。是否收到微信物流通知，还取决于官方权限、用户订阅及实际运单状态，当前未验收通知。
- 商城订单进度仍由商家操作更新；快递签收不自动等于商城确认收货。微信官方页面的布局由微信控制，不是在自制时间线里伪造物流数据。
- 官方文档只允许查询本小程序购物订单。模拟付款、其他渠道订单不使用该能力。频次限制为每 AppID 每日 10 万次、每用户每日 100 次（以官方实时政策为准）。

## 开通后验收

使用自己的真实付款及实际运单，检查：发货和单号复制、买家一键打开官方页面、商品卡片回到正确订单、重复查看、补发换号、其他买家拒绝访问、权限失效与网络失败提示。未完成真实付款/开通前，只能验证接口替身与错误路径，不应标记生产查询已可用。
