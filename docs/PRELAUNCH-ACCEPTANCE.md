# 模拟版上线前验收

范围遵循 [必要功能与开发边界](SCOPE.md)。真实微信身份、支付、退款渠道及其账号申请单独处理；以下项目不能因接口测试通过就算全部完成。

| 项目 | 当前证据 | 仍需完成 |
| --- | --- | --- |
| 建品、上下架、图片与模板 | 三方隔离测试覆盖建品和下架；既有 Web 可操作 | 继续检查真实素材、规格填写与失败提示 |
| 购买与取消 | 实际开发者工具创建并取消订单，Web 与 MongoDB 同步；弱网重试自动测试 | 真机网络切换验收 |
| 商家外送与自提 | 隔离 HTTP/MongoDB 全流程，错误提货码拒绝，正确核销一致 | 实际小程序与 Web 完整点击验收 |
| 基础售后、退货入库 | 审核、退回、验收、模拟退款及重复回调测试 | 实际界面完整点击验收 |
| 门店经营设置 | 地址、电话、营业时间、自提外送开关及费用，版本冲突测试 | 核对实际门店资料及规则说明 |
| 日常库存 | 新增进货、可售盘点、报损与流水，网页重试恢复，MongoDB 并发测试 | 新 Node 生效后的点击验收，见 [库存说明](INVENTORY.md) |
| 异常履约 | 缺货、外送失败、自提改期、联系未果的处理入口与记录，实际数量退款及三方隔离测试通过 | 运行服务更新后的实际界面验收，见 [履约问题](FULFILLMENT-ISSUES.md) |
| 数据规模 | 订单列表与库存流水数据库分页 | 去除开发容量上限，并避免写入与定时任务反复加载全部历史数据 |
| 网络与进程 | 超时、有限读重试、写请求防重、MongoDB 重连、健康检查 | Node、MongoDB、隧道的守护及主机重启恢复验收 |
| 备份与恢复 | 完整业务、图片、账号哈希和审计备份；共享库独立恢复已验证；自动周期与保留策略测试通过 | 服务更新后确认定时任务执行；异机副本与主机故障恢复，见 [恢复说明](BACKUP-RECOVERY.md) |
| 上线资料 | 已明确必要范围与模拟边界 | 店铺隐私、售后和配送说明；正式部署配置与账号权限复核 |

## 验收规则

- 每条路径必须有商品、金额、订单状态、库存与权限的对应检查，不能只看页面提示“成功”。
- 修改数据的自动化使用新建的测试库；共享环境测试保留明确的模拟订单和操作记录，不清库、不重置商品。
- 保留已验证的小程序侧请求协议。新增能力可通过版本能力标记启用，运行中的旧服务不应因新 Web 静态文件而失去原功能。
- 完整自动测试、实际界面、真机和运行环境分开记录。未验证的项目保持待验收，不能写成已经可正式上线。
